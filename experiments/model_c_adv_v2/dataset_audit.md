# C-Adv v2 Dataset Audit Report

## 1. Generation Method
Genuine and Different Person samples were drawn directly from the properly aligned baseline manifest.
Impersonation samples were generated by extracting 10 target identities per source identity, running Native InsightFace InSwapper (128x128 resolution) on the context crop.

## 2. Preprocessing Method
Crucially, unlike v1, the synthesized InSwapper output frame is passed through `app.get()` to locate the new face landmarks, and then passed through `align_face()`. This ensures all three classes (`genuine`, `different_person`, `impersonation`) enter the model strictly as 112x112 aligned face crops, closing the structural bounding-box leakage.

## 3. Source/Target Identity Rules
- Reference Identity: The physical identity of the source enrolled gallery image.
- Physical Target Identity: The physical person whose body is in the webcam frame.
- For impersonation: The reference identity face is swapped onto the physical target identity body.

## 4. Split Rules
Identities are strictly disjoint across Train, Val, and Test splits.

## 5. Class Counts
### Train
- Genuine: 1161
- Different Person: 870
- Impersonation: 297

### Validation
- Genuine: 386
- Different Person: 90
- Impersonation: 96

### Test
- Genuine: 387
- Different Person: 90
- Impersonation: 100

## 6. Representation Consistency Checks
Programmatic tests confirm that 100% of the newly generated impersonation images in `face_swaps_v2/` are exactly 112x112x3, matching the geometry of the genuine dataset.

## 7. Duplicate Checks
No duplicate sample IDs were found.

## 8. Leakage Checks
No class can be trivially identified from dimensions or crop geometry. File encodings are standardized to OpenCV's default BGR JPEG encoding across all classes.
